1. WPROWADZENIE

Celem projektu było stworzenie kompletnego serwisu REST API opartego na platformie Amazon Web Services (AWS), który wykorzystuje samodzielnie wytrenowany model uczenia maszynowego do klasyfikacji sentymentu recenzji filmowych.

Dane wejściowe stanowią recenzje filmów z serwisu IMDb – model określa, czy recenzja wyraża opinię pozytywną, negatywną lub neutralną, zwracając wynik wraz z poziomem pewności predykcji.

Projekt realizuje pełny pipeline przetwarzania danych i wdrożenia modelu:
- pobranie i eksploracja surowych danych,
- proces ETL (Extract, Transform, Load) z wykorzystaniem AWS Glue (Apache Spark),
- trening i optymalizacja modeli ML w środowisku Amazon SageMaker,
- zapisanie artefaktów modelu w Amazon S3,
- udostępnienie modelu jako bezserwerowe REST API (AWS Lambda + API Gateway).

2. OPIS ZBIORU DANYCH

Zbiór danych: IMDB Dataset of 50K Movie Reviews
Źródło: Kaggle / Stanford AI Lab
Liczba rekordów: 50 000 recenzji filmowych
Klasy: positive (pozytywna) / negative (negatywna)
Balans klas: 25 000 pozytywnych / 25 000 negatywnych (idealnie zbalansowany)

Struktura danych:
Kolumna "review"    – tekst recenzji filmowej (string)
Kolumna "sentiment" – etykieta klasy: "positive" lub "negative"

Recenzje zawierają tekst w języku angielskim o zmiennej długości. Surowe dane zawierają tagi HTML (<br />), znaki specjalne oraz słowa funkcyjne (stopwords), które zostają usunięte w procesie ETL.

Statystyki długości recenzji (po preprocessingu):
- Średnia długość: ~117 słów
- Mediana: ~97 słów
- Maksymalna długość: ~1 408 słów

4. PRZETWARZANIE DANYCH ETL – AWS GLUE

AWS Glue jest zarządzaną usługą ETL opartą na Apache Spark, przeznaczoną do przetwarzania dużych zbiorów danych (Big Data). W projekcie zaimplementowano job Glue realizujący następujące transformacje:

Etapy pipeline'u ETL:

1. Ekstrakcja (Extract)
   - Wczytanie surowego pliku CSV z Amazon S3
   - Format: s3://imdb-sentiment-zubriichuk/data/IMDB Dataset.csv
   - Użycie Spark DataFrame z opcją multiLine

2. Transformacja (Transform)
   - Usunięcie tagów HTML: <br />, <br>
   - Usunięcie znaków niealfabetycznych (cyfry, interpunkcja)
   - Zamiana na małe litery (lowercase normalization)
   - Usunięcie nadmiarowych białych znaków
   - Kodowanie etykiet: positive → 1, negative → 0
   - Inżynieria cech: liczba słów (word_count), długość oryginału

3. Ładowanie (Load)
   - Zapis przetworzonych danych do S3: s3://imdb-sentiment-zubriichuk/processed/
   - Format CSV z nagłówkiem, tryb overwrite

Kod Glue (fragment):
    df = df.withColumn('review_clean', regexp_replace(col('review'), r'<br\s*/?>', ' '))
    df = df.withColumn('review_clean', regexp_replace(col('review_clean'), r'[^a-zA-Z\s]', ''))
    df = df.withColumn('review_clean', lower(col('review_clean')))
    df = df.withColumn('target', when(col('sentiment') == 'positive', 1).otherwise(0))
    df = df.withColumn('word_count', size(split(col('review_clean'), ' ')))

Wynik: Glue job zakończony ze statusem Succeeded – przetworzone 50 000 rekordów.

6. INŻYNIERIA CECH – WEKTORYZACJA TF-IDF

Do reprezentacji tekstowej zastosowano metodę TF-IDF (Term Frequency – Inverse Document Frequency).

Parametry wektoryzatora:
- max_features: 5 000
- ngram_range: (1, 2) – unigramy i bigramy
- Preprocessing: lowercase, usunięcie stopwords, lematyzacja WordNet

Kroki preprocessingu tekstu przed wektoryzacją:
1. Zamiana na małe litery
2. Usunięcie tagów HTML (<br />)
3. Usunięcie znaków niealfabetycznych
4. Usunięcie angielskich stopwords (NLTK)
5. Lematyzacja (WordNetLemmatizer)

Podział danych:
- Zbiór treningowy: 80% (40 000 rekordów)
- Zbiór testowy: 20% (10 000 rekordów)
- Stratified split – zachowanie proporcji klas w obu zbiorach

7. TRENOWANIE MODELI UCZENIA MASZYNOWEGO

Wytrenowano dwa modele klasyfikacji z optymalizacją hiperparametrów
metodą GridSearchCV (walidacja krzyżowa k=3):

7.1 Regresja Logistyczna (Logistic Regression)
Siatka hiperparametrów:
- C:       [0.01, 0.1, 1, 10]
- penalty: [l2]

Regresja logistyczna jest liniowym modelem klasyfikacji szczególnie
skutecznym dla danych wysokowymiarowych (sparse TF-IDF matrices).
Parametr C kontroluje siłę regularyzacji – wyższe C = słabsza regularyzacja.

7.2 Las Losowy (Random Forest)
Siatka hiperparametrów:
- n_estimators:      [50, 100]
- max_depth:         [10, 20, None]
- min_samples_split: [2, 5]

Las losowy to ensemble model oparty na wielu drzewach decyzyjnych,
odporny na przeuczenie dzięki mechanizmowi baggingu i losowego wyboru cech.

10. TESTOWANIE API

Format żądania:
  POST /prod/predict
  Content-Type: application/json
  Body: {"review": "tekst recenzji"}

Format odpowiedzi:
  {
    "sentiment": "positive" | "negative" | "neutral",
    "confidence": 0-100,
    "probabilities": {
      "negative": X.XX,
      "positive": X.XX
    },
    "review_preview": "pierwsze 100 znaków..."
  }

Przykłady testowe:

Test 1 – recenzja pozytywna:
  Wejście:  {"review": "This movie was absolutely fantastic! Great acting and amazing story."}

Test 2 – recenzja negatywna:
  Wejście:  {"review": "Terrible movie, waste of time, awful acting"}
  Wynik:    {"sentiment": "negative", "confidence": 99.99}

Test 3 – krótka recenzja pozytywna:
  Wejście:  {"review": "great movie"}
  Wynik:    {"sentiment": "positive", "confidence": 97.77}

Model poprawnie klasyfikuje wszystkie przypadki testowe
z wysoką pewnością predykcji (>97%).

12. PODSUMOWANIE I WNIOSKI

Projekt zakończył się pełnym wdrożeniem systemu klasyfikacji sentymentu
recenzji filmowych jako serwisu REST API w chmurze AWS.

Zrealizowane elementy:
[x] Działający endpoint API dostępny pod adresem HTTPS
[x] Wykorzystanie 5 serwisów AWS: S3, Glue, SageMaker, Lambda, API Gateway
[x] Kontrola wersji z publicznym repozytorium GitHub
[x] Pipeline ETL z użyciem AWS Glue (Apache Spark) i notebooka SageMaker
[x] Rozwiązanie Big Data: przetwarzanie 50 000 rekordów za pomocą PySpark
[x] Model ML wytrenowany i zoptymalizowany (GridSearchCV) w SageMaker
[x] Analiza i ocena wyników (confusion matrix, ROC, feature importance)

Wnioski techniczne:

1. Regresja logistyczna z regularyzacją L2 okazała się lepszym wyborem
   niż las losowy dla klasyfikacji tekstu wysokowymiarowego (TF-IDF).

2. Bigramy w TF-IDF istotnie poprawiają jakość modelu, pozwalając na
   uchwycenie kontekstu negacji (np. „not good", „never boring").

3. Architektura bezserwerowa (Lambda + API Gateway) jest kosztowo
   efektywna – płatność tylko za rzeczywiste wywołania API.

4. Lambda Layer jako mechanizm dostarczania zależności wymaga
   starannego zarządzania rozmiarem (~183 MB po optymalizacji)
   i zgodnością wersji Python oraz scikit-learn.

5. AWS Glue z Apache Spark umożliwia skalowalne przetwarzanie danych –
   ta sama architektura obsłużyłaby setki milionów rekordów bez zmian
   w kodzie.
